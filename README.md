# Полное руководство по реализации системного вызова 'reg' в xv6

## Введение: что вы создадите

Вы реализуете системный вызов `reg()`, который позволяет процессу читать значения регистров **s2-s11** из указанного процесса. Это учебное задание демонстрирует ключевые концепции операционных систем: изоляцию процессов, контроль доступа, и безопасную передачу данных между пространством пользователя и ядром.

---

## Часть 1: Фундаментальные концепции

### 1.1 Что такое системные вызовы и зачем они нужны

**Системный вызов** — это контролируемый механизм, через который пользовательские программы запрашивают сервисы у ядра операционной системы.

**Почему они существуют:**

1. **Абстракция железа**: Программы используют `read()` и `write()` вместо прямой работы с контроллерами дисков
2. **Защита ресурсов**: Предотвращение прямого доступа пользовательских программ к чувствительным ресурсам
3. **Контролируемое взаимодействие**: Безопасный способ для программ взаимодействовать с ядром
4. **Разделение привилегий**: Переход из непривилегированного пользовательского режима в привилегированный режим ядра

**Как это работает в xv6:**
```
Пользовательская программа → ecall (trap) → 
  Аппаратура повышает привилегии → 
  Ядро обрабатывает запрос → 
  sret возвращает в пользовательский режим
```

### 1.2 Разделение user-space и kernel-space

xv6 строго разделяет два мира:

**User Space (Пространство пользователя):**
- Где выполняются приложения
- Ограниченные привилегии
- Не может напрямую обращаться к железу или памяти ядра
- Виртуальные адреса начинаются с 0

**Kernel Space (Пространство ядра):**
- Где выполняется код ОС
- Полные привилегии
- Доступ ко всей памяти и устройствам
- Отображается по высоким адресам (выше KERNBASE)

**Организация адресного пространства:**
```
0x00000000        ← User Space Start
    [text]        ← Код программы
    [data]        ← Глобальные переменные  
    [heap]        ← Динамическая память (растет вверх)
    [stack]       ← Стек функций (растет вниз)
...
0x80000000        ← KERNBASE (Kernel Space Start)
    [kernel text] ← Код ядра
    [kernel data] ← Структуры данных ядра
TRAMPOLINE        ← Код для переключения режимов
TRAPFRAME         ← Сохраненное состояние процесса
```

**Ключевая идея**: Ядро отображено в адресное пространство каждого процесса, но пользовательский код не может его читать благодаря аппаратной защите.

### 1.3 Виртуальная память и таблицы страниц

**Виртуальная память** создает иллюзию, что каждый процесс имеет свой собственный компьютер с памятью, начинающейся с адреса 0.

**Как это работает:**
- **Виртуальные адреса**: Адреса, с которыми работают программы
- **Физические адреса**: Реальные адреса в RAM
- **Таблицы страниц**: Аппаратные структуры данных для преобразования виртуальных адресов в физические
- **Размер страницы**: 4096 байт (4 KB)

**Флаги Page Table Entry (PTE):**
- **PTE_V**: Запись действительна
- **PTE_R**: Readable (можно читать)
- **PTE_W**: Writable (можно писать)
- **PTE_X**: Executable (можно исполнять)
- **PTE_U**: User accessible (доступно в пользовательском режиме)

**Преимущества виртуальной памяти:**
1. **Изоляция**: Каждый процесс имеет свое адресное пространство
2. **Простота**: Программы видят непрерывные адреса начиная с 0
3. **Защита**: Память ядра защищена от пользовательского доступа через флаг PTE_U
4. **Гибкость**: Один и тот же виртуальный адрес в разных процессах указывает на разную физическую память

### 1.4 Почему нельзя напрямую разыменовывать указатели из user-space в kernel-space

**Проблема безопасности №1**: Злонамеренный или ошибочный код может передать ядру невалидный указатель или указатель, предназначенный для обмана ядра и доступа к памяти ядра.

**Проблема безопасности №2**: Таблицы страниц ядра и пользователя отличаются. Указатель, валидный в пользовательской таблице страниц, может быть невалидным или указывать на неверную память в таблице страниц ядра.

**Пример проблемы:**
```c
// ОПАСНО! Никогда так не делайте:
uint64 sys_bad_example(void) {
    uint64 user_ptr;
    argaddr(0, &user_ptr);
    
    // Попытка напрямую разыменовать user_ptr в ядре
    int value = *(int*)user_ptr;  // ← ОШИБКА! Может вызвать page fault
    return value;
}
```

**Правильное решение — функции copyout() и copyin():**

Эти функции:
1. Получают таблицу страниц пользователя как параметр
2. Используют `walkaddr()` для преобразования виртуального адреса → физический
3. Безопасно копируют данные, используя физический адрес
4. Проверяют, что адрес находится в пользовательском адресном пространстве

```c
// ПРАВИЛЬНО:
uint64 sys_safe_example(void) {
    uint64 user_ptr;
    int kernel_value;
    struct proc *p = myproc();
    
    argaddr(0, &user_ptr);
    
    // Безопасная копия из пользовательского пространства
    if(copyin(p->pagetable, &kernel_value, user_ptr, sizeof(int)) < 0)
        return -1;
    
    return kernel_value;
}
```

### 1.5 Уровни привилегий и защитные механизмы

**RISC-V предоставляет три режима привилегий:**

1. **Machine Mode (M-mode)**: Наивысший уровень, полный доступ к железу
2. **Supervisor Mode (S-mode)**: Где выполняется код ядра
3. **User Mode (U-mode)**: Где выполняются приложения

**Что НЕ МОЖЕТ делать User Mode:**
- Исполнять привилегированные инструкции (изменять таблицы страниц, отключать прерывания)
- Обращаться к памяти без установленного флага PTE_U
- Напрямую обращаться к железу
- Изменять управляющие регистры (satp, sstatus и т.д.)

**Что МОЖЕТ делать Supervisor Mode:**
- Все инструкции пользовательского режима плюс привилегированные
- Доступ ко всей памяти (пользовательской и ядра)
- Настройка таблиц страниц и MMU
- Обработка прерываний и трапов
- Доступ к управляющим регистрам (CSR)

**Переход через системный вызов:**
```
1. Пользовательская программа выполняет ecall
2. Аппаратура автоматически:
   - Сохраняет текущий PC в регистр sepc
   - Устанавливает режим supervisor
   - Устанавливает PC на stvec (адрес обработчика трапа)
   - Отключает прерывания
3. Обработчик трапа ядра исполняется (в S-mode)
4. После обработки, инструкция sret:
   - Восстанавливает PC из sepc
   - Возвращается в пользовательский режим
   - Включает прерывания обратно
```

## Часть 2: Архитектура xv6 и системные вызовы

### 2.1 Полный путь системного вызова

**Пошаговый процесс выполнения:**

```
USER SPACE:
┌─────────────────────────────────────────────────┐
│ fork()                    ← Пользовательская программа │
│   ↓                                             │
│ Обертка (из usys.pl):                           │
│   li a7, SYS_fork          ← Загрузить номер syscall │
│   ecall                    ← Trap в ядро        │
│   ret                                           │
└─────────────────────────────────────────────────┘
              ↓ ecall
┌─────────────────────────────────────────────────┐
│ HARDWARE (RISC-V):                              │
│ • Сохранить PC в sepc                           │
│ • Установить режим supervisor                   │
│ • Перейти на stvec                              │
└─────────────────────────────────────────────────┘
              ↓
KERNEL SPACE:
┌─────────────────────────────────────────────────┐
│ Trampoline (trampoline.S):                      │
│   uservec:                                      │
│   • Сохранить все регистры в trapframe          │
│   • Переключиться на kernel page table          │
│   • Загрузить kernel stack                      │
│   • Вызвать usertrap()                          │
└─────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────┐
│ usertrap() (trap.c):                            │
│   • Определить тип трапа                        │
│   • Для системных вызовов: вызвать syscall()    │
└─────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────┐
│ syscall() (syscall.c):                          │
│   num = p->trapframe->a7      ← Получить номер  │
│   p->trapframe->a0 = syscalls[num]()            │
│                     ↓                           │
│   syscalls[SYS_fork] → sys_fork()               │
└─────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────┐
│ sys_fork() (sysproc.c):                         │
│   • Извлечь аргументы (если есть)               │
│   • Вызвать fork()                              │
│   • Вернуть результат                           │
└─────────────────────────────────────────────────┘
              ↓ возврат
┌─────────────────────────────────────────────────┐
│ Путь возврата:                                  │
│   • usertrapret() готовит возврат               │
│   • userret() восстанавливает регистры          │
│   • sret возвращается в user mode               │
└─────────────────────────────────────────────────┘
```

### 2.2 Ключевые структуры данных

#### struct proc - Структура процесса

Определена в `kernel/proc.h`. Представляет процесс:

```c
struct proc {
  struct spinlock lock;        // Блокировка для этого процесса
  enum procstate state;        // Состояние процесса
  void *chan;                  // Канал, на котором спит процесс
  int killed;                  // Был ли процесс убит
  int xstate;                  // Статус выхода для parent's wait
  int pid;                     // Process ID
  struct proc *parent;         // Родительский процесс
  uint64 kstack;               // Адрес kernel stack
  uint64 sz;                   // Размер памяти процесса (байты)
  pagetable_t pagetable;       // Таблица страниц пользователя
  struct trapframe *trapframe; // Сохраненные регистры
  struct context context;      // Контекст для переключения
  struct file *ofile[NOFILE];  // Открытые файлы
  struct inode *cwd;           // Текущий каталог
  char name[16];               // Имя процесса (для отладки)
};
```

**Ключевые поля:**
- **pid**: Идентификатор процесса
- **parent**: Указатель на структуру родительского процесса
- **pagetable**: Таблица страниц процесса (для преобразования виртуальных адресов)
- **trapframe**: Указатель на сохраненное состояние регистров
- **state**: Текущее состояние (UNUSED, SLEEPING, RUNNABLE, RUNNING, ZOMBIE)

#### struct trapframe - Сохраненное состояние регистров

Определена в `kernel/proc.h`. Сохраняет ВСЕ пользовательские регистры при трапе:

```c
struct trapframe {
  /*   0 */ uint64 kernel_satp;   // kernel page table
  /*   8 */ uint64 kernel_sp;     // top of kernel stack
  /*  16 */ uint64 kernel_trap;   // usertrap()
  /*  24 */ uint64 epc;            // сохраненный program counter
  /*  32 */ uint64 kernel_hartid; 
  /*  40 */ uint64 ra;             // return address
  /*  48 */ uint64 sp;             // stack pointer
  /*  56 */ uint64 gp;             
  /*  64 */ uint64 tp;             
  /*  72 */ uint64 t0;             // temporary registers
  /*  80 */ uint64 t1;
  /*  88 */ uint64 t2;
  /*  96 */ uint64 s0;             // saved registers
  /* 104 */ uint64 s1;
  /* 112 */ uint64 a0;             // аргументы/возврат
  /* 120 */ uint64 a1;
  /* 128 */ uint64 a2;
  /* 136 */ uint64 a3;
  /* 144 */ uint64 a4;
  /* 152 */ uint64 a5;
  /* 160 */ uint64 a6;
  /* 168 */ uint64 a7;             // номер системного вызова
  /* 176 */ uint64 s2;             // ← s2 здесь!
  /* 184 */ uint64 s3;
  /* 192 */ uint64 s4;
  /* 200 */ uint64 s5;
  /* 208 */ uint64 s6;
  /* 216 */ uint64 s7;
  /* 224 */ uint64 s8;
  /* 232 */ uint64 s9;
  /* 240 */ uint64 s10;
  /* 248 */ uint64 s11;            // ← s11 здесь!
  /* 256 */ uint64 t3;
  /* 264 */ uint64 t4;
  /* 272 */ uint64 t5;
  /* 280 */ uint64 t6;
};
```

**Почему trapframe содержит все регистры:**
При возврате в пользовательское пространство ядро напрямую восстанавливает регистры из trapframe, не раскручивая весь стек вызовов. Поэтому должны быть сохранены ВСЕ регистры, включая s2-s11 (callee-saved регистры).

### 2.3 RISC-V регистры s2-s11

**Calling Convention (соглашение о вызовах):**
- **s0-s11**: Saved registers (callee-saved) - функция, использующая их, должна их сохранить
- **a0-a7**: Argument/return registers (caller-saved) - передача аргументов
- **t0-t6**: Temporary registers (caller-saved) - временные значения

**Таблица соответствия регистров для нашего задания:**

| register_num | ABI Name | x-number | Смещение в trapframe | Доступ |
|--------------|----------|----------|---------------------|---------|
| 2 | s2 | x18 | 176 | `p->trapframe->s2` |
| 3 | s3 | x19 | 184 | `p->trapframe->s3` |
| 4 | s4 | x20 | 192 | `p->trapframe->s4` |
| 5 | s5 | x21 | 200 | `p->trapframe->s5` |
| 6 | s6 | x22 | 208 | `p->trapframe->s6` |
| 7 | s7 | x23 | 216 | `p->trapframe->s7` |
| 8 | s8 | x24 | 224 | `p->trapframe->s8` |
| 9 | s9 | x25 | 232 | `p->trapframe->s9` |
| 10 | s10 | x26 | 240 | `p->trapframe->s10` |
| 11 | s11 | x27 | 248 | `p->trapframe->s11` |

### 2.4 Ключевые функции ядра

#### myproc() - Получить текущий процесс

**Местоположение**: `kernel/proc.c`

```c
struct proc* myproc(void) {
  push_off();  // Отключить прерывания
  struct cpu *c = mycpu();
  struct proc *p = c->proc;
  pop_off();   // Включить прерывания
  return p;
}
```

**Использование:**
```c
struct proc *p = myproc();  // Получить текущий процесс
int pid = p->pid;           // Доступ к PID
```

#### copyout() - Копирование данных из ядра в user-space

**Местоположение**: `kernel/vm.c`

**Сигнатура:**
```c
int copyout(pagetable_t pagetable, uint64 dstva, char *src, uint64 len);
```

**Параметры:**
- `pagetable`: Таблица страниц пользователя для записи
- `dstva`: Целевой виртуальный адрес в user-space
- `src`: Источник в kernel-space
- `len`: Количество байт для копирования

**Возврат**: 0 при успехе, -1 при ошибке

**Как это работает:**
1. Округляет адрес вниз до границы страницы
2. Использует `walkaddr()` для преобразования виртуального адреса → физический
3. Проверяет валидность адреса
4. Копирует данные, используя физический адрес
5. Обрабатывает границы страниц

**Пример:**
```c
struct proc *p = myproc();
uint64 user_addr;
int kernel_value = 42;

argaddr(0, &user_addr);  // Получить адрес от пользователя

// Безопасно скопировать в user-space
if(copyout(p->pagetable, user_addr, (char*)&kernel_value, sizeof(int)) < 0)
    return -1;
```

#### argint() / argaddr() - Извлечение аргументов системного вызова

**Местоположение**: `kernel/syscall.c`

**Сигнатуры:**
```c
int argint(int n, int *ip);       // Извлечь целочисленный аргумент
int argaddr(int n, uint64 *ip);   // Извлечь адрес/указатель
```

**Как это работает:**
- Аргументы передаются в регистрах a0-a6 (сохранены в trapframe)
- Аргумент 0 → a0, Аргумент 1 → a1, и т.д.
- Возвращаемое значение также в a0

**Пример использования:**
```c
uint64 sys_example(void) {
    int int_arg;
    uint64 addr_arg;
    
    // Извлечь аргументы
    if(argint(0, &int_arg) < 0)
        return -1;
    if(argaddr(1, &addr_arg) < 0)
        return -1;
    
    // Использовать аргументы...
    return 0;
}
```

## Часть 3: Пошаговая реализация системного вызова 'reg'

### Шаг 1: Определить номер системного вызова

**Файл: kernel/syscall.h**

Добавьте в конец файла:
```c
#define SYS_reg 22
```

**Объяснение**: Каждый системный вызов имеет уникальный номер. xv6 имеет 21 встроенный системный вызов (fork, exit, wait, ..., close), поэтому мы используем 22. Этот номер будет загружен в регистр a7 пользовательской оберткой.

### Шаг 2: Добавить прототип и диспетчеризацию

**Файл: kernel/syscall.c**

**2a. Добавить внешнее объявление** (в начале файла, где другие extern):
```c
extern uint64 sys_reg(void);
```

**2b. Добавить в таблицу диспетчеризации** (в массиве syscalls[]):
```c
static uint64 (*syscalls[])(void) = {
    [SYS_fork]    sys_fork,
    [SYS_exit]    sys_exit,
    // ... другие системные вызовы ...
    [SYS_close]   sys_close,
    [SYS_reg]     sys_reg,     // ← Добавить эту строку
};
```

**Объяснение**: Когда системный вызов происходит, функция `syscall()` читает номер из регистра a7 и использует его как индекс в этом массиве, чтобы вызвать правильную функцию.

**Опционально: Добавить имя для отладки**:
```c
static char *syscall_names[] = {
    [SYS_fork]    "fork",
    [SYS_exit]    "exit",
    // ...
    [SYS_reg]     "reg",       // ← Добавить для отладочных сообщений
};
```

### Шаг 3: Добавить объявление вспомогательной функции

**Файл: kernel/defs.h**

Найдите секцию с объявлениями из proc.c (около других функций типа allocproc, fork, и т.д.) и добавьте:

```c
// proc.c
// ... существующие объявления ...
uint64          reg(int pid, int register_num, uint64 *return_value);
```

**Объяснение**: Мы создадим вспомогательную функцию `reg()` в proc.c, которая будет выполнять основную работу. Объявление в defs.h делает ее видимой для других файлов ядра.

### Шаг 4: Реализовать обертку системного вызова

**Файл: kernel/sysproc.c**

Добавьте в конец файла:

```c
uint64
sys_reg(void)
{
  int pid;
  int register_num;
  uint64 return_value_addr;
  
  // Извлечь аргументы из регистров, сохраненных в trapframe
  // Аргумент 0: int pid
  if(argint(0, &pid) < 0)
    return -1;
  
  // Аргумент 1: int register_num  
  if(argint(1, &register_num) < 0)
    return -1;
  
  // Аргумент 2: uint64 *return_value (указатель)
  if(argaddr(2, &return_value_addr) < 0)
    return -1;
  
  // Вызвать вспомогательную функцию для выполнения работы
  return reg(pid, register_num, return_value_addr);
}
```

**Объяснение по строкам:**
- **argint(0, &pid)**: Извлекает первый аргумент (pid) из регистра a0
- **argint(1, &register_num)**: Извлекает второй аргумент из регистра a1
- **argaddr(2, &return_value_addr)**: Извлекает третий аргумент (указатель) из регистра a2
- Проверяем каждый `< 0` для обработки ошибок при извлечении аргументов
- Вызываем вспомогательную функцию `reg()`, которая реализует логику

### Шаг 5: Реализовать основную функцию

**Файл: kernel/proc.c**

Добавьте в конец файла (перед `#endif` если есть):

```c
// Системный вызов reg: получить значения регистров s2-s11
// Возвращает 0 при успехе, отрицательные коды ошибок
uint64
reg(int pid, int register_num, uint64 return_value_addr)
{
  struct proc *p = myproc();  // Текущий процесс (вызывающий)
  struct proc *target = 0;    // Целевой процесс (чьи регистры читаем)
  uint64 reg_value;           // Значение регистра для возврата
  
  // Шаг 1: Валидация номера регистра (должен быть 2-11)
  if(register_num < 2 || register_num > 11) {
    return -3;  // -3 если некорректный номер регистра
  }
  
  // Шаг 2: Найти целевой процесс по PID
  // Итерируем по таблице процессов
  for(target = proc; target < &proc[NPROC]; target++) {
    acquire(&target->lock);  // Захватить блокировку для безопасного доступа
    
    if(target->state != UNUSED && target->pid == pid) {
      // Нашли процесс с нужным PID
      
      // Шаг 3: Проверка безопасности - может читать только:
      // (а) свои собственные регистры (pid == текущий процесс)
      // (б) регистры непосредственного дочернего процесса
      if(target != p && target->parent != p) {
        release(&target->lock);
        return -1;  // -1 если нет прав доступа
      }
      
      // Шаг 4: Извлечь значение регистра из trapframe
      // Используем switch для выбора правильного поля
      switch(register_num) {
        case 2:  reg_value = target->trapframe->s2;  break;
        case 3:  reg_value = target->trapframe->s3;  break;
        case 4:  reg_value = target->trapframe->s4;  break;
        case 5:  reg_value = target->trapframe->s5;  break;
        case 6:  reg_value = target->trapframe->s6;  break;
        case 7:  reg_value = target->trapframe->s7;  break;
        case 8:  reg_value = target->trapframe->s8;  break;
        case 9:  reg_value = target->trapframe->s9;  break;
        case 10: reg_value = target->trapframe->s10; break;
        case 11: reg_value = target->trapframe->s11; break;
        default:
          // Не должно случиться (уже проверили), но для безопасности
          release(&target->lock);
          return -3;
      }
      
      release(&target->lock);  // Освободить блокировку
      
      // Шаг 5: Скопировать значение в user-space
      // ВАЖНО: Нельзя напрямую писать по return_value_addr!
      // Используем copyout для безопасной передачи данных
      if(copyout(p->pagetable, return_value_addr, 
                 (char*)&reg_value, sizeof(reg_value)) < 0) {
        return -4;  // -4 если не удалось записать данные
      }
      
      return 0;  // Успех!
    }
    
    release(&target->lock);
  }
  
  // Если мы здесь, процесс с данным PID не найден
  return -2;  // -2 если процесс не существует
}
```

**Подробные объяснения:**

**Шаг 1 - Валидация:**
```c
if(register_num < 2 || register_num > 11) {
    return -3;
}
```
Проверяем, что register_num в диапазоне 2-11. Это соответствует регистрам s2-s11.

**Шаг 2 - Поиск процесса:**
```c
for(target = proc; target < &proc[NPROC]; target++) {
    acquire(&target->lock);
```
- Таблица процессов — статический массив `proc[NPROC]` (обычно 64 процесса)
- Итерируем по всем процессам
- **Важно**: Захватываем блокировку перед доступом к полям процесса (многопоточная безопасность)

**Шаг 3 - Проверка безопасности:**
```c
if(target != p && target->parent != p) {
    return -1;
}
```
Проверяем две разрешенные ситуации:
- `target != p`: Процесс читает свои собственные регистры (всегда разрешено)
- `target->parent != p`: Процесс читает регистры своего непосредственного дочернего процесса

Если ни одно условие не выполнено → возврат -1 (нет прав).

**Важность этой проверки**: Без нее любой процесс мог бы читать регистры любого другого процесса, что является серьезной брешью в безопасности. Регистры могут содержать чувствительную информацию (указатели, данные, и т.д.).

**Шаг 4 - Извлечение значения регистра:**
```c
switch(register_num) {
    case 2:  reg_value = target->trapframe->s2;  break;
    // ...
}
```
- Доступ к trapframe целевого процесса
- Выбираем правильное поле на основе register_num
- Сохраняем в локальную переменную `reg_value`

**Шаг 5 - Копирование в user-space:**
```c
if(copyout(p->pagetable, return_value_addr, 
           (char*)&reg_value, sizeof(reg_value)) < 0) {
    return -4;
}
```
**Критически важно**: Не можем делать `*return_value_addr = reg_value`!

Причины:
1. `return_value_addr` — это адрес в user-space (виртуальный адрес пользователя)
2. В контексте ядра этот адрес может быть невалидным
3. Должны использовать `copyout()`, который:
   - Берет таблицу страниц текущего процесса (`p->pagetable`)
   - Преобразует виртуальный адрес в физический
   - Безопасно копирует данные
   - Проверяет валидность адреса

Создайте новый файл:
```c
#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"

int
main(int argc, char *argv[])
{
  uint64 value;
  int result;
  
  printf("=== Test 1: Reading own registers ===\n");
  // Тест 1: Процесс читает свои собственные регистры (должно работать)
  for(int reg_num = 2; reg_num <= 11; reg_num++) {
    result = reg(getpid(), reg_num, &value);
    if(result == 0) {
      printf("Register s%d = %p (success)\n", reg_num, value);
    } else {
      printf("Register s%d failed with code %d\n", reg_num, result);
    }
  }
  
  printf("\n=== Test 2: Invalid register number ===\n");
  // Тест 2: Невалидный номер регистра (должен вернуть -3)
  result = reg(getpid(), 0, &value);
  printf("Invalid register 0: %d (expected -3)\n", result);
  
  result = reg(getpid(), 12, &value);
  printf("Invalid register 12: %d (expected -3)\n", result);
  
  printf("\n=== Test 3: Non-existent process ===\n");
  // Тест 3: Несуществующий процесс (должен вернуть -2)
  result = reg(99999, 2, &value);
  printf("Non-existent PID 99999: %d (expected -2)\n", result);
  
  printf("\n=== Test 4: Parent reading child ===\n");
  // Тест 4: Родитель читает дочерний процесс (должно работать)
  int pid = fork();
  if(pid == 0) {
    // Дочерний процесс - просто ждет
    sleep(5);
    exit(0);
  } else {
    // Родитель пытается прочитать регистры дочернего
    sleep(1);  // Дать дочернему время запуститься
    result = reg(pid, 2, &value);
    printf("Parent reading child s2: result=%d, value=%p\n", result, value);
    wait(0);
  }
  
  printf("\n=== Test 5: Reading another process (should fail) ===\n");
  // Тест 5: Попытка прочитать регистры непривилегированного процесса
  // Создаем независимый процесс
  pid = fork();
  if(pid == 0) {
    sleep(10);
    exit(0);
  } else {
    int pid2 = fork();
    if(pid2 == 0) {
      // Второй дочерний пытается прочитать первого (должно отказать)
      sleep(2);
      result = reg(pid, 2, &value);
      printf("Sibling reading sibling: %d (expected -1)\n", result);
      exit(0);
    }
    wait(0);
    wait(0);
  }
  
  printf("\n=== All tests completed ===\n");
  exit(0);
}
```

**Объяснение тестов:**

**Тест 1**: Проверяет, что процесс может читать свои собственные регистры (базовая функциональность).

**Тест 2**: Проверяет валидацию номера регистра (0 и 12 недопустимы, должны вернуть -3).

**Тест 3**: Проверяет обработку несуществующего PID (должен вернуть -2).

**Тест 4**: Проверяет, что родитель может читать регистры дочернего процесса (разрешенная операция).

**Тест 5**: Проверяет, что процесс НЕ может читать регистры процесса, который не является его непосредственным дочерним (должен вернуть -1).

## Часть 4: Проверки безопасности и их важность

### 4.1 Почему проверки безопасности критичны

**Принцип наименьших привилегий**: Процесс должен иметь доступ только к минимуму ресурсов, необходимых для выполнения его задачи.

**Без проверок безопасности в нашем системном вызове:**
- Любой процесс мог бы читать регистры любого другого процесса
- Регистры могут содержать указатели на конфиденциальные данные
- Злонамеренный процесс мог бы извлекать информацию из других процессов
- Нарушение изоляции процессов — основного принципа ОС

### 4.2 Реализованные проверки

**Проверка 1: Валидация номера регистра**
```c
if(register_num < 2 || register_num > 11) {
    return -3;
}
```
**Зачем**: Предотвращает доступ к произвольным полям в trapframe. Без этой проверки злоумышленник мог бы указать произвольное смещение и прочитать другие данные.

**Проверка 2: Существование процесса**
```c
if(target->state != UNUSED && target->pid == pid)
```
**Зачем**: Убеждаемся, что процесс существует перед доступом к его данным. Без этого можем попытаться прочитать из неинициализированной памяти.

**Проверка 3: Права доступа**
```c
if(target != p && target->parent != p) {
    return -1;
}
```
**Зачем**: Реализует policy доступа - процесс может читать только:
1. Свои регистры (нужно для самоанализа, отладки)
2. Регистры дочерних процессов (родитель управляет дочерними, может их мониторить)

Это предотвращает:
- Чтение регистров непривилегированных процессов
- Утечку информации между процессами
- Нарушение изоляции процессов

**Проверка 4: Безопасная передача данных**
```c
if(copyout(p->pagetable, return_value_addr, ...) < 0) {
    return -4;
}
```
**Зачем**: 
- Проверяет валидность пользовательского адреса
- Предотвращает запись в память ядра (если пользователь передал адрес ядра)
- Обрабатывает невалидные указатели безопасно

### 4.3 Важность блокировок

```c
acquire(&target->lock);
// ... доступ к полям процесса ...
release(&target->lock);
```

**Зачем нужны блокировки:**
- xv6 — многопроцессорная система
- Несколько CPU могут одновременно выполнять код ядра
- Без блокировок возможны **race conditions** (состояния гонки):
  - Процесс может быть изменен или освобожден во время чтения
  - Можем прочитать частично обновленные данные
  - Можем обратиться к освобожденной памяти

**Пример race condition без блокировки:**
```
CPU 1: Читает target->trapframe->s2
CPU 2: Процесс завершается, освобождается trapframe
CPU 1: Пытается прочитать - SEGFAULT!
```

**Ошибка 1: "unknown sys call X"**

- **Решение**: Проверьте, что SYS_reg правильно определен и добавлен в syscalls[]

- **Причина**: Забыли добавить extern или реализовать sys_reg()

- **Решение**: Добавьте $_U/regtest\ в секцию UPROGS

- **Причина**: Неправильное извлечение аргументов
- **Решение**: Проверьте порядок аргументов в argint/argaddr - они должны совпадать с объявлением

**Ошибка 5: Kernel panic или page fault**
- **Возможные причины**:
  1. Забыли acquire/release блокировки
  2. Напрямую разыменовываете пользовательский указатель
  3. Доступ к освобожденной памяти
- **Решение**: Всегда используйте блокировки, всегда используйте copyout/copyin

## Часть 6: Расширенные концепции и улучшения

### 6.1 Почему именно s2-s11?

**Callee-saved регистры** имеют специальное назначение:
- Функции должны их сохранять (в отличие от caller-saved)
- Используются для долгоживущих значений
- Важны для корректной работы программ
- Их чтение может быть полезно для отладки или профилирования

### 6.2 Возможные расширения

**Расширение 1: Чтение всех регистров сразу**
```c
struct all_regs {
    uint64 s2, s3, s4, s5, s6, s7, s8, s9, s10, s11;
};

int reg_all(int pid, struct all_regs *regs);
```

**Расширение 2: Запись регистров**
```c
// Для отладчиков - позволить родителю модифицировать регистры дочернего
int reg_write(int pid, int register_num, uint64 value);
```

**Расширение 3: Чтение всех регистров, включая временные**
```c
int reg_extended(int pid, int register_num, uint64 *value);
// register_num 0-31 для всех x0-x31
```

### 6.3 Реальные применения

**Отладчики (debuggers)**: gdb использует похожий механизм (ptrace в Linux) для:
- Установки breakpoints
- Чтения/записи регистров отлаживаемой программы
- Пошагового выполнения

**Профилировщики**: Могут семплировать регистры для анализа производительности

**Мониторинг**: Родительский процесс может мониторить состояние дочерних

**kernel/sysproc.c:**
```c
uint64
sys_reg(void)
{
  int pid, register_num;
  uint64 return_value_addr;
  
  if(argint(0, &pid) < 0)
    return -1;
  if(argint(1, &register_num) < 0)
    return -1;
  if(argaddr(2, &return_value_addr) < 0)
    return -1;
  
  return reg(pid, register_num, return_value_addr);
}
```

**kernel/proc.c:**
```c
uint64
reg(int pid, int register_num, uint64 return_value_addr)
{
  struct proc *p = myproc();
  struct proc *target = 0;
  uint64 reg_value;
  
  if(register_num < 2 || register_num > 11)
    return -3;
  
  for(target = proc; target < &proc[NPROC]; target++) {
    acquire(&target->lock);
    if(target->state != UNUSED && target->pid == pid) {
      if(target != p && target->parent != p) {
        release(&target->lock);
        return -1;
      }
      
      switch(register_num) {
        case 2:  reg_value = target->trapframe->s2;  break;
        case 3:  reg_value = target->trapframe->s3;  break;
        case 4:  reg_value = target->trapframe->s4;  break;
        case 5:  reg_value = target->trapframe->s5;  break;
        case 6:  reg_value = target->trapframe->s6;  break;
        case 7:  reg_value = target->trapframe->s7;  break;
        case 8:  reg_value = target->trapframe->s8;  break;
        case 9:  reg_value = target->trapframe->s9;  break;
        case 10: reg_value = target->trapframe->s10; break;
        case 11: reg_value = target->trapframe->s11; break;
        default:
          release(&target->lock);
          return -3;
      }
      
      release(&target->lock);
      
      if(copyout(p->pagetable, return_value_addr, 
                 (char*)&reg_value, sizeof(reg_value)) < 0)
        return -4;
      
      return 0;
    }
    release(&target->lock);
  }
  
  return -2;
}
```
